# Загрузка витрины P64 в SQL Server 2022 Developer

18 ноября 2026 года полный Linux CI на iMac выполнил `ssas-mdx-sales-cube_20261118-170528`. В сводке обе задачи имеют статус `JOB_ok`. Офлайн-задача выполнила 20 тестов за 1,02 с и проверила форматирование и линтинг Ruff. В задаче `mssql` прошли 6 тестов за 7,49 с. [Сводка, журналы pytest, расчёт эталона и уборка стенда](mssql-evidence.zip)

Образ SQL Server 2022 CU18 закреплён по digest `sha256:ea73825f3d88a23c355ac2f9fdc6bd960fec90171c12c572109b36a558f77bb8`. Тест создал пустую базу `P64SalesDW` и выполнил `sqlcmd -d P64SalesDW -b -i sql/load.sql`. Скрипт установил схему и загрузил подготовленные генератором вставки с seed 64. Тест прочитал таблицы SQL Server в порядке первичного ключа и сравнил каждое поле с исходными строками. [Загрузчик](../../sql/load.sql) · [Проверки](../../tests/test_mssql.py)

| Таблица | Строк в эталоне | Результат чтения из SQL Server |
|---|---:|---|
| DimDate | 731 | Все даты, ключи и подписи совпали |
| DimProduct | 6 | Все товары и категории совпали |
| DimCustomer | 4 | Все клиенты и регионы совпали |
| FactSales | 1 838 | Ключи, количество и выручка совпали в каждой продаже |

При повторной загрузке SQL Server вернул ошибку 2714 о существующем объекте. Тест заново прочитал все четыре таблицы и подтвердил сохранность исходных строк. При выборе пустой базы `P64WrongTarget` загрузчик завершился с сообщением о необходимости выбрать `P64SalesDW`. После этого в `sys.tables` контрольной базы было ноль таблиц. Compose удалил контейнер и сеть.

Для архива исходников `tree.tgz` локально и на iMac получен SHA-256 `d22f948abdb961fd1c838814164319541e8c77b3f5f8c33c051c0453ba1b019f`. С рабочими файлами побайтово сверены все 33 файла архива вне Markdown. Следующий этап требует экземпляра SSAS Multidimensional с доступом к загруженной базе для ProcessFull, выполнения десяти запросов MDX и подключения Excel. [Порядок проверки](../MANUAL_STEPS.md)
